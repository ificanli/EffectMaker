## 2. 教程最终传达的视觉逻辑

教程不是先堆一张“发光刀片”，而是先建立打击因果：

```text
起势/进入
 -> 主体刀光建立轮廓
 -> 接近目标
 -> 快速打击层和局部高光短暂出现
 -> 命中峰值
 -> 主体保持可读窗口
 -> 暗层、溶解、地面反馈和光晕慢速退出
```

关键判断：

- 快速进入、短命中峰值、慢退场形成打击落差；
- 主体轮廓优先于内部纹理、Bloom 和氛围光；
- 暗层/灰层用于托住亮层，不是用来增加画面数量；
- 快速打击层必须遵循主节奏，不能与主体同时铺满；
- 亮度过高会吞掉饱和度、纹理和轮廓；
- 溶解应服务退场方向，不能在主体尚未成立时提前破坏形体；
- 主体强度与氛围光是两个独立控制问题；
- 地面反馈和受击点是攻击方向的空间回声，不能抢主体焦点。

## 3. 按时间段的完整学习结果

### 3.1 00:00–20:00：先建立打击节奏

证据等级：高（语音和复核记录一致）。

教程事实：

- `01:15–01:35`：先思考起势、命中爆发、可读窗口和收尾，再做外观细节。
- `06:00–09:00`：主体快速接近/命中，之后慢速退出；残留层的展示时间可以独立控制。
- `10:00–12:20`：高光和命中峰值快速进入，残留不能与高光使用同一退场节奏。
- `12:20–15:40`：命中曝光应该短而适度；长时间高强度会让画面失去层次。
- `15:40–20:00`：暗层、灰过渡和亮层共同建立明暗对比；暗层过亮会发灰，亮层过亮会失去局部焦点。

可执行映射：

- 先用纯色主体验证完整生命周期；
- 将主体和残留做成独立控制；
- 先调时间曲线，再调颜色和贴图；
- 至少采集进入、命中、收束三个时间点。

未确认：具体 Duration、Curve 关键点、Burst 数量、Emission 和完整 Timeline 值。

### 3.2 20:00–40:00：颜色职责与主体几何

证据等级：高/中。

教程事实：

- `20:10–22:16`：颜色分为主色、辅助色和点缀色。
- 主色传达属性和主题；辅助色负责过渡和丰富；点缀色承担少量对比和焦点强化。
- `20:44–21:37`：作者举例约 `60/30/10`，只是案例比例，不能当固定规范。
- `26:00–30:00`：从空粒子系统开始，让粒子承载模型/平面；主体优先使用清晰的刀光平面或模型。
- 模型长度、宽度和分段要支持点位形变；细分过低会在变形时拉伸。
- `30:00–40:00`：使用模型发射器、Local 空间，并调整方向和尺寸；先建立粗轮廓。
- `40:00` 左右：可以通过删除局部点、挖洞或修改轮廓改变主体造型，但必须以播放态检查。

可执行映射：

- `SlashRoot/Core` 使用 MeshRenderer 或 Mesh ParticleSystem；
- 模型记录 Pivot、轴向、UV0、细分和法线；
- 主体先用不透明/纯色材质，禁止依赖 Bloom 证明轮廓；
- 颜色先用职责层记录，不直接复制 `60/30/10` 为数值。

未确认：教程工程中的具体模型文件、顶点数、面数、Prefab 名、粒子 Shape 数值。

### 3.3 40:00–60:00：颜色图层、Mask、UV、Custom Data 与溶解

证据等级：高/中。

教程事实：

- 颜色可以拆成独立图层，基础色、渐变和方向/角度分别调整。
- `50:40–51:03`：Mask 方向需要旋转，出现 `90°` 立起的处理。
- `51:04–51:26`：通过 Custom Data/自定义曲线控制 X 轴位移；不需要的轴向控制应关闭。
- `51:28–52:34`：贴图没有铺满 UV 范围时修正 Offset；素材切边时继续推 UV 可能使图案移出模型边界，应回到贴图和 UV 一起处理。
- `52:41–52:47`：字幕出现约 `Lifetime=0.4`、`Size=5`，但 Inspector 模块上下文不完整，暂定为线索而非教程事实。
- `52:50–53:05`：快入慢出由曲线控制，不能用匀速替代。
- `54:18–55:01`：噪声/点状内部纹理和流速有约 `1`、`1.5`、`2` 的案例比较，但纹理名和字段映射不可靠。
- `55:30–60:00`：尾部向前溶解；通过 Mask、软边、暗色和流动控制退场；主体先完整成立，再进入溶解。

可执行映射：

- `CustomData.x` 只控制一个明确方向；
- 将 UV 速度、Offset、Dissolve Threshold 和顶点偏移分开记录；
- 溶解至少需要方向、阈值、边缘宽度和保留窗口四个控制项；
- 先关闭噪声和顶点偏移，确认主体，再逐层加入。

未确认：Shader 的正式名称（ASR 出现“熊猫”等不可靠词）、Blend、Queue、ZWrite、Cull、ZTest、贴图文件名、通道映射和完整曲线。

### 3.4 60:00–70:00：主体、暗层、多功能贴图

证据等级：高。

教程事实：

- 主体先保持可读，再复制层加入内部星线或多功能贴图。
- 多功能贴图要保留主贴图轮廓，同时增加内部纹理，不能让纹理夺走主体主色。
- 灰/暗支撑层应更慢、落后、生命周期更长。
- UV 流动速度必须回到播放态验证；过快会形成无意义拉丝。
- 溶解层应先保留一段时间，再进入退场。
- HDR、颜色、溶解和流动必须小步调整。

可执行映射：

- `Core`、`DarkSupport`、`InternalDetail` 独立开关；
- 先只显示 `Core`，再加入 `DarkSupport`，最后加入内部纹理；
- 每次截图至少包含静态轮廓和连续运动两个证据。

### 3.5 70:00–80:00：暗底层与延后快速打击层

证据等级：高；使用第二轮准确回补字幕。

教程事实：

- `71:21–72:50`：复制主体层和材质，建立暗底；暗层使用 Alpha 模式。
- 暗层颜色整体更暗，但过暗会发脏，需要回调；溶解应更明显、更柔和；层级向下调整。
- 顶点偏移过高会产生漂浮感，需要降低。
- `73:00–75:45`：主体过快时回调速度和位移，基础主层暂时稳定后才进入快速打击层。
- `76:20–77:25`：明确有两小层快速打击层；它们在主体接近目标/命中位置时才逐渐显现，不与主体同时出现。
- `77:25–79:20`：快速层使用更简单的贴图；复制对象后清空不需要的材质功能，只保留一张贴图；调整 X 轴尺寸、流动、整体大小和位置。
- 通过 Custom Data 控制 X 轴位移，关闭不用的轴向控制；加入 `0.1s` 延迟。
- `79:20–80:00`：单向 Mask 用于修正方向和位置，出现 `180`、`270` 方向试验；位置偏差要单独解决。

可执行映射：

```text
Core 主体
  -> DarkBase 暗底
  -> FastStrike_A
  -> FastStrike_B
```

这是教程职责结构的工程映射，不是教程 Hierarchy 原样抄录。两层快速打击层必须可以单独关闭和单独截图。

### 3.6 80:00–90:00：局部亮层、暗层、氛围光和遮罩

证据等级：高/中高。

教程事实：

- `80:00–82:30`：使用单向 Mask 修正两侧遮罩和方向；尝试 `90°` 立起；一层遮罩不够时可以叠加第二层。
- 黑色区域用于遮掉模型，保留少量白色/可见区域；重点是反复调 UV 方向，而不是盲目提高强度。
- Bloom/亮度过高会吞掉细节和饱和度，需要回调亮度，可少量补饱和度。
- `83:00–84:30`：复制主体层增加小暗层，改 Alpha，放到主体下方；Custom 曲线用于错开或延迟 UV 流动。
- `85:30–86:30`：刀光本体强度和氛围光独立；氛围可以由小气浪和小氛围光承担。
- `87:25–89:00`：辅助层可以使用简单剑片贴图和 Add 模式；贴图可旋转 `180°`，再用遮罩控制局部，可叠第二张遮罩。

未确认：具体辅助层对象数量、实际 Shader 名、贴图资产名、HDR 数值和完整层级顺序。

### 3.7 90:00–100:00：辅助光、方向和低强度 Glow

证据等级：高/中。

教程事实：

- 先校正尺寸、3D Rotation 和位置，再加低强度 Glow。
- 复制层后改变方向，使用蓝/蓝紫作为辅助色，并降低明度。
- 逐帧检查出现、角度、大小和光晕时序。
- 点光/辅助发射器属于独立层，不能用主体材质代替。

未确认：点光对象是否由 Timeline、脚本或粒子事件触发；具体强度、衰减和范围字段。

### 3.8 100:00–110:00：命中点、点光和地面反馈

证据等级：高/中。

教程事实：

- 点光和受击反馈独立于主体；暖红向黄过渡，短时快速弹出。
- 约 `1.25` 的整体强度是课程案例线索，不是通用值。
- 辅助层可以稍微拉长，但不能拖慢命中。
- 地面反馈可以先用简单平面、一张贴图和材质完成。
- 地面滑痕是主体攻击方向的空间回声，不应提前抢焦点。

低置信数字：字幕中的 `0.35`、`0.5`、`75` 无法可靠映射到具体字段。

### 3.9 110:00–120:00：受击点形状与三曲线

证据等级：高/中低。

教程事实：

- 受击点长度和宽度分开调整。
- Size 使用三曲线模式；X/Y 轴对应的空间方向需要在目标工程中回读确认。
- 可复制基础受击层，增加低强度 Glow、颜色曲线、轻微拉长、错位和下沉。
- 黑白贴图/Mask 中，白色可见、黑色透明。
- `Size=3`、比例约 `2` 只作为案例线索，不能直接写成固定参数。

### 3.10 120:00–128:01：地面平面、路径和亮边

证据等级：高/中。

教程事实：

- 一张贴图和一个贴地平面可以承担第一版地面反馈，不必一开始制作复杂模型。
- 平面需要通过 3D Rotation 或脚本调整朝向。
- 路径可以导出为 AI 文件，转为面/模型后检查表面方向、厚度、UV 和颜色。
- 复制亮边层，用 Mask 控制范围、透明度/强度、颜色和低速流动。
- 立体感来自面域、层级、遮罩和空间关系，不是简单提亮。

## 4. 教程结构的当前工程映射

以下不是教程原始 Hierarchy，而是根据职责建立的可执行试验结构：

```text
BladeRoot
  CoreBody                 主体轮廓，先建立可读窗口
  DarkBase                 暗底支撑，Alpha，低亮度，慢速/延迟
  FastStrike_A             接近命中时出现的简单贴图层
  FastStrike_B             第二个错位/不同方向的快速层
  EdgeHighlight            局部亮边和高光，Mask 控制范围
  InternalDetail           多功能贴图/星线/内部纹理
  Atmosphere               小气浪和氛围光，短、淡、独立
  HitPoint                 命中点、点光、受击局部反馈
  GroundFeedback           地面滑痕/贴地平面
  Residual                 溶解和慢速残留
```

已确认的职责关系：`CoreBody` 先出现；`DarkBase` 后跟且更慢；`FastStrike_A/B` 靠近命中点出现；`EdgeHighlight` 只保留局部；`Atmosphere` 不代替主体；`GroundFeedback` 和 `HitPoint` 服务命中；`Residual` 慢退。

仍未知：教程实际是否将这些职责合并在同一 ParticleSystem、是否使用 Panda/自有 Shader、具体 GameObject 数量和 Prefab 层级。

## 6. 材质、Shader 与纹理信息边界

教程已经教会的工作流：

- 主体先用主贴图建立轮廓，再复制材质给暗层/亮层；
- 暗层使用 Alpha 逻辑，快速辅助层可以使用 Add；
- 多功能贴图承担内部纹理，不能破坏主轮廓；
- Mask 用于方向、局部保留和溶解；
- UV 方向、Offset、Custom Data 和播放速度必须联动检查；
- Bloom/Emission 只做局部高光，不承担主体可读性；
- 地面反馈先用一张黑白贴图和贴地平面验证。

教程仍未可靠给出：

- Shader 正式名称；
- 材质资产名称和路径；
- 贴图文件名、分辨率、通道映射、Wrap/Filter、sRGB；
- Blend 的完整 Inspector 配置；
- Render Queue、ZWrite、ZTest、Cull；
- 完整 HDR、溶解边缘、噪声尺度和顶点动画值。

这些字段允许先用工程占位实现，但必须标记 `assumption` 或 `unknown`，并在 Unity 中回读。

## 7. 参数试验协议

每轮只改变一个问题：

```text
轮廓
 -> 时间/速度
 -> 暗层关系
 -> 快速打击层时序
 -> Mask/UV
 -> 溶解
 -> 亮度/HDR
 -> 命中点/地面反馈
```

每次试验必须记录：

- `trial_id`、日期、场景、效果和层；
- Unity 参数路径、修改前值、修改后值；
- 假设依据和证据时间戳；
- 采样请求时间和截图 manifest；
- 人工判断：轮廓、方向、占屏、峰值、收束、遮蔽、拉丝、发脏、过曝；
- 改善项、副作用、下一步和是否保留。

确定性截图不能只看 PNG 存在或像素变化，必须人工确认连续运动。

## 8. 已知失败模式

- 用三秒成品帧反推教程参数；
- 用现有 `OrangeSlash_Final` 五层结构冒充教程真实层级；
- 把 Whisper 的错误数字或专业词当作 Inspector 字段；
- 把 `0.4`、`5`、`1.25` 等案例线索直接升级为硬参数；
- 同时修改模型、相机、材质、粒子和后处理，导致无法判断因果；
- 用 Bloom、HDR、颜色堆叠掩盖主体轮廓问题；
- 用固定等待时间截图，错过短生命周期；
- 把空字幕当作无语音；
- 把 Prefab、ParticleSystem 数量、PNG 或编译成功当作视觉通过。
