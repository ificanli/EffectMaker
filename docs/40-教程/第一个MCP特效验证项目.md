# 第一个 Unity CLI 特效验证项目

## 目标

在 Unity 中建立一个最小的能量爆发效果，优先使用 Unity CLI 完成项目检查、Editor 命令、构建和测试；只有 CLI 不覆盖的实时编辑器操作才使用 Unity MCP。

> 创建 → 检查 → 运行 → 观察 → 修改 → 保存

这个项目的首要目标是验证 MCP 和 Unity 的协作能力，视觉内容保持简单但必须包含层次。

## 工具选择

1. 检查环境和项目：`unity doctor`、`unity editors --format json`、`unity projects verify <project>`。
2. 创建、打开或构建项目：优先 Unity CLI。
3. 需要实时读取或修改层级、组件、材质和运行状态：使用 Unity MCP。
4. 结果确认：读取 CLI 退出码、Unity Console、场景/资源文件和运行画面。

MCP 不是默认工具，也不能替代 Unity Editor 的 license、运行结果和人工质量判断。


- 一个核心能量球或发光网格。
- 一个外层能量环或冲击波。
- 一组短生命周期火花。
- 一个简单的地面反馈。
- 一个固定摄像机和中性测试环境。

## 建议制作顺序

1. 创建测试场景和根对象 `VFX_Test_EnergyBurst`。
2. 创建核心对象，设置位置、尺寸和发光材质。
3. 创建外层环或冲击波，设置透明材质和缩放动画。
4. 创建火花粒子，设置初始速度、生命周期、数量和颜色。
5. 添加地面反馈，确认效果与场景空间关系正确。
6. 运行场景，检查核心、主体、细节和环境层是否按顺序出现。
7. 修改一个明显参数，例如爆发规模或火花数量，再次运行对比。
8. 保存场景、材质和预制体。
9. 将实际成功和失败的 MCP 操作记录到能力验证清单。

## 验证重点

- MCP 能否读取新建对象和组件。
- MCP 能否修改粒子和材质参数。
- 修改是否在运行画面中生效。
- 保存后重新加载是否保留结果。
- Console 是否出现错误或警告。
- 效果是否能在静帧下看出核心和冲击方向。

## 完成标准

- 场景可运行且无阻断性错误。
- 至少有核心、辅助和环境三个层次。
- 至少完成一次有记录的参数迭代。
- 结果保存为可复用预制体或明确记录无法保存的原因。
- 完成一次质量检查和一次基础性能检查。

## 后续扩展

完成最小闭环后，再加入噪声流动、扭曲、动态光、摄像机震动和 Timeline。不要在 MCP 能力尚未验证时直接引入所有复杂系统。
