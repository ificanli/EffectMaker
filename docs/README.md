# Unity 特效 AI 学习工程

## 项目定位

本工程用于建立一套"需求驱动、可验证、可复用、可持续学习"的 Unity 特效生产系统。

最终目标不是让 AI 一次生成某个特效，而是让 AI 能够围绕视觉需求完成：

> 需求输入 → 视觉拆解 → 技术选型 → Unity 制作 → 运行验证 → 质量评估 → 参数迭代 → 性能检查 → 资源沉淀

## 总目标

1. 掌握 Unity 特效的视觉设计和技术实现方法。
2. 通过 Unity CLI 管理 Unity 项目、Editor、模块、认证、构建和命令；必要时再通过 Unity MCP 操作实时编辑器和项目资源。
3. 建立可重复的特效制作、验证、迭代流程。
4. 将成熟方案沉淀为预制体、材质、Shader、参数规范和文档。
5. 默认通过 Unity CLI 完成项目管理、环境诊断、构建、测试和可注册命令；仅在 CLI 不覆盖实时编辑器操作时使用 Unity MCP。
6. 逐步形成可迁移到不同技能和项目的特效资产库。

## 架构总览

```text
资料输入
  ├─ 审美类（点评/参考）
  │    → 判断规则 → 检查清单 → 失败模式库
  ├─ 制作类（教程/实战）
  │    → 步骤模板 → 参数范围 → 技术组合
  └─ 交叉验证
       → 审美规则 × 制作实践 = 稳定知识
       → Unity CLI 项目/Editor/构建验证
       → Unity MCP 实时编辑器补充操作
       → 运行结果与人工质量评估
```

详见 [双管道学习架构](30-操作指南/双管道学习架构.md)。

## 使用规则

- 方法论文档描述稳定原则；具体效果文档描述实际项目经验。
- 任何结论都应尽量附带验证场景、截图、参数或性能数据。
- 失败方案也要记录，避免重复试错。
- 资料必须先登记来源、授权、版本和适用范围，再进入吸收流程。
- 审美类和制作类资料使用不同的处理管道，但通过交叉验证统一结论。
- 资料知识只有经过证据定位和实践验证，才可升级为项目规范或可复用能力。
- 当 Unity 版本、渲染管线或 MCP 能力变化时，及时更新对应参考文档和受影响的知识卡片。
