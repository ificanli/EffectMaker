# 参数与命名规范

本规范用于提高 MCP 操作的稳定性、Inspector 查找效率和资源复用能力。若具体项目已有规范，应以项目规范为准，并在效果文档中说明例外。

## 目录建议

```text
Assets/
  Art/VFX/
    Materials/
    Shaders/
    Textures/
    Meshes/
    Prefabs/
    Scenes/
  Scripts/VFX/
  Tests/VFX/
```

## 命名建议

- 预制体：`VFX_<用途>_<主体>`，例如 `VFX_Combat_EnergyBurst`。
- 材质：`M_VFX_<主体>_<用途>`，例如 `M_VFX_Energy_Additive`。
- Shader：`SG_VFX_<用途>` 或 `SH_VFX_<用途>`。
- 纹理：`T_VFX_<内容>_<用途>`，例如 `T_VFX_Noise_Distortion`。
- 测试场景：`VFX_Test_<主题>`。
- 根对象：与预制体同名，避免使用无意义的 `GameObject`。
- 子层：使用 `Core`、`Body`、`Detail`、`Environment`、`Camera` 等稳定名称。

## 参数命名

- 尺寸：`Size`、`Radius`、`Width`、`Length`。
- 时间：`Duration`、`Delay`、`Lifetime`、`FadeIn`、`FadeOut`。
- 运动：`Speed`、`Acceleration`、`Spread`、`RotationSpeed`。
- 视觉：`Color`、`Intensity`、`Opacity`、`Emission`。
- 变化：`NoiseScale`、`NoiseStrength`、`Distortion`、`Dissolve`。
- 性能：`MaxParticles`、`SimulationSpace`、`LOD`。

## 参数原则

1. 同一含义使用同一个名字。
2. 影响整体效果的参数优先放在根配置或统一控制器中。
3. 避免把同一个视觉概念分散成多个难以同步的参数。
4. 参数范围应有明确上下限，并记录默认值。
5. 不暴露不会被调节或没有实际意义的内部参数。

## 版本和记录

成熟效果保存为预制体后，应同时记录：Unity 版本、渲染管线、目标平台、依赖资源、关键参数和已知限制。
