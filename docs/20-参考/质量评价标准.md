# 质量评价标准

## A. 视觉评价

| 检查项 | 通过标准 |
|---|---|
| 识别度 | 一眼能看出效果用途或材质倾向 |
| 轮廓 | 静帧下主体形状清楚，不依赖过曝 |
| 颜色 | 主色、辅助色和亮部有层级 |
| 材质 | 火焰、能量、烟雾、金属等表现符合语义 |
| 层次 | 核心、主体、细节和环境有空间关系 |
| 场景融合 | 不像贴在画面上的独立图层 |

## B. 动态评价

| 检查项 | 通过标准 |
|---|---|
| 前摇 | 观众能感知即将发生的动作 |
| 爆发 | 关键时刻有明确视觉峰值 |
| 持续 | 主体信息不会瞬间消失或混乱 |
| 收尾 | 亮度、规模和速度自然衰减 |
| 节奏 | 各层之间有先后关系，不是同时出现和消失 |
| 镜头适配 | 目标镜头距离下始终可读 |

## C. 工程评价

- 关键参数集中且可调。
- 对象、材质、粒子系统和预制体命名清楚。
- 资源依赖明确，没有隐藏的场景引用。
- 可以独立播放或通过标准事件触发。
- 能保存为预制体并在另一个测试位置复用。

## D. 性能评价

至少记录：

- 平均和峰值粒子数量。
- 透明材质和粒子系统数量。
- Overdraw 情况。
- Shader 和后处理成本。
- 目标设备或目标平台的帧率表现。
- 是否存在明显的内存、GC 或加载问题。

## 评分方式

每个维度使用 1 到 5 分：

- 1 分：明显不可用。
- 2 分：有基础结果，但问题突出。
- 3 分：功能可用，质量一般。
- 4 分：质量稳定，存在少量可改善项。
- 5 分：达到当前目标，适合沉淀复用。

总分不能替代问题清单。任何导致读图失败、严重穿帮或性能超标的问题，都必须单独记录，即使平均分较高。
