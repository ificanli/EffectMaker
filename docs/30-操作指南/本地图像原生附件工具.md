# 本地图像原生附件工具

## 用途

`read_local_image` 只负责读取本地图片文件，与 Unity、场景、相机和浏览器无关。它通过现有 Unity MCP server 的自动发现机制注册，并返回 FastMCP 原生 `Image` 结果，最终由 MCP 转换为：

```json
{
  "type": "image",
  "data": "<base64 PNG/JPEG data>",
  "mimeType": "image/png"
}
```

这里的 base64 只存在于 MCP 协议的 `ImageContent` 内部，不是普通 JSON 字段，也不是返回本地路径。

## 文件

- `workspace/unity-verification/Packages/com.coplaydev.unity-mcp/UnityMcpServer~/src/tools/read_local_image.py`
- `workspace/tools/image_attachment_server.py`：不依赖 MCP SDK 的协议核心和本地测试辅助
- `workspace/tests/test_image_attachment_server.py`
- `workspace/tests/test_native_image_tool_contract.py`

## 工具调用

工具参数只有一个：

```text
path: 本地图片路径
```

支持 `.png`、`.jpg`、`.jpeg`、`.webp`、`.gif` 和 `.bmp`。文件不存在、路径不是文件或扩展名不支持时直接返回错误，不修改输入文件。

## 接入边界

现有 server 启动时会自动扫描 `src/tools/`，因此新文件会被 `register_all_tools` 发现。运行时依赖由该 server 的 `pyproject.toml` 提供：`mcp[cli]>=1.15.0,<2`。

当前工作区默认 Python 环境没有安装 `mcp` 包，因此本轮完成了协议代码、静态注册契约和真实 PNG 字节验证，但没有声称当前 ZCode 已经加载了新工具。宿主需要使用现有 Unity MCP server 的 Python 环境启动后，工具才会出现在工具列表中。

## 验证

```bash
python -m unittest workspace.tests.test_image_attachment_server workspace.tests.test_native_image_tool_contract -v
```

真实 Unity PNG 已验证：返回类型为 `image`，MIME 为 `image/png`，解码后的字节与原文件完全一致。
