# 统一媒体工具

`workspace/tools/media.py` 集中处理视频证据流水线中的 FFmpeg/ffprobe 调用，`media_cli.py` 提供命令行入口。

## 工具路径

按以下顺序查找：

1. 环境变量 `VFX_FFMPEG` / `VFX_FFPROBE`。
2. 系统 `PATH`。
3. 项目当前使用的 ShareX 路径。
4. WinGet 安装的 Gyan FFmpeg 路径。

## 常用命令

```bash
python -m workspace.tools.media_cli probe input.mp4 --output media_meta.json
python -m workspace.tools.media_cli frame input.mp4 12.5 frames/00-00-12.jpg
python -m workspace.tools.media_cli audio input.mp4 audio/input_16k_mono.wav
python -m workspace.tools.media_cli cut-audio audio/input_16k_mono.wav 0 600 audio/part_000-600.wav
python -m workspace.tools.media_cli cut-video input.mp4 120 135 clips/case_a.mp4
```

`probe` 输出的元数据包含来源、容器格式、时长、视频分辨率/FPS/编码，以及音频编码、采样率和声道数。时间区间使用秒，要求 `start >= 0` 且 `end > start`。

## 场景边界与资料导入

PySceneDetect 和 MarkItDown 是媒体/资料流水线的可选扩展依赖，统一安装方式为：

```bash
python -m pip install -r requirements-media.txt
```

检测视频场景边界，输出可追溯的 JSON 和 CSV。边界是候选证据窗口，仍需人工确认其是否对应前摇、爆发、受击或收束：

```bash
python -m workspace.tools.media_integrations_cli scenes \
  "<video_path>" "<source_dir>/scenes"
```

导入普通文档时，转换结果默认写入 `knowledge/inbox/`，不会自动改变资料状态、创建知识卡片或写入稳定规范：

```bash
python -m workspace.tools.media_integrations_cli import-document \
  "<document_path>" --knowledge-root knowledge
```

Markdown、纯文本、CSV、JSON 和 XML 走原样导入；其他支持的格式交给 MarkItDown 转换为 Markdown。复杂扫描 PDF、OCR 和版式敏感资料暂不由这条入口保证，需单独评估 Docling。

已有 `build_episode_evidence.py` 会额外生成 `media_meta.json`；原有 OpenCV 客观指标和 FFmpeg 联系图逻辑保持不变。

## 单集可恢复检查点

使用 `episode_checkpoint.py` 扫描单集当前状态，记录固定时间窗口的转写分段和后续产物状态：

```bash
python workspace/tools/episode_checkpoint.py 10 \
  --source-root knowledge/sources/SRC-2026-SERIES-001
```

命令会写入 `ep010/episode_manifest.json`，并报告 `complete`、`empty`、`missing` 分段数量。分段文件按转写器的固定窗口命名，最后一个窗口允许超过视频实际结束时间。该检查点只读扫描并写入 manifest，不删除文件、不自动合并字幕、不替代人工视觉审核，也不自动关闭 Beads 任务。
