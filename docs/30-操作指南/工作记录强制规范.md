# 工作记录强制规范

把"每阶段写结果、完成写结论、弯路必记录"固化为 Beads 任务的强制要求。

## 为什么

- 任务反复走的弯路是宝贵经验：记录它，防止自己和其他窗口重复踩坑。
- 任务关闭后，做的内容、产出和结论必须能从任务本身追溯，而不是只存在于对话里。
- bd 1.2.2 原生没有必填校验，靠本规范 + `bdg` 门禁在工具层强制。

## 记录位置

| 内容 | 字段 | 命令 |
|------|------|------|
| 阶段结论、弯路记录 | 备注（notes） | `bdg note <id> "..."` |
| 交流讨论、过程沟通 | 评论（comments） | `bdg comment <id> "..."` |
| 关闭原因 / 完成结论 | close reason | `bdg close <id> --reason "..."` |

阶段记录和评论**两者都用**：备注存结论与弯路，评论存交流过程。

## 弯路记录格式

每个任务的备注里用固定小节承载弯路记录：

```text
## 弯路记录
- [2026-08-25] 尝试 A 方案 → 失败（现象/根因）→ 纠正为 B → 结果
- [2026-08-26] 走了弯路：用 C 方法，发现 D 限制，改走 E
```

原则：记下"试了什么、为什么不行、改成什么、结果如何"，而不是只写一句"走了弯路"。

## 强制规则（bdg 门禁）

| 命令 | 强制内容 |
|------|---------|
| `bdg create` | 必须带 `--description`（做什么）、`--acceptance`（验收标准）、`--notes`（含阶段/弯路记录），缺任一拒绝创建 |
| `bdg close` | 必须带 `--reason`（关闭原因/完成结论），缺则拒绝关闭 |
| `bdg close --require-notes` | 额外要求任务已有结论性记录（备注/评论含"完成/产出/沉淀/弯路/结果/记录"等词且长度足够），否则拒绝关闭 |
| `bdg note` / `bdg comment` | 内容为空时拒绝 |
| `bdg update <id> --acceptance ... --notes ...` | 仅修订验收标准，两字段均须非空；备注追加而非覆盖，不允许通过此入口修改状态 |

## 使用

```bash
# 创建任务（三字段必填）
python -m workspace.tools.bd_guard create "标题" \
  --description "做什么" --acceptance "验收标准" --notes "阶段/弯路记录"

# 或通过启动脚本（Windows）
workspace/bdg.bat create "标题" --description "..." --acceptance "..." --notes "..."

# 每完成一个阶段，追加结果
python -m workspace.tools.bd_guard note <id> "阶段结论：转写完成；弯路：CUDA缺cublas→改CPU"

# 补齐或修订验收标准，保留原状态和历史备注
python -m workspace.tools.bd_guard update <id> --acceptance "验收标准" --notes "记录：修订依据和影响范围"

# 关闭前确认有结论，再关闭
python -m workspace.tools.bd_guard close <id> --reason "完成：产出...，结论已沉淀" --require-notes
```

## 定期检查

```bash
python -m workspace.tools.bd_guard guard-check            # 文本报告
python -m workspace.tools.bd_guard guard-check --format json
```

列出所有不合规任务（缺验收标准 / closed 缺 close_reason / closed 无结论记录）。带 `legacy` 标签的历史任务跳过。

## 历史任务

- 已存在的历史不合规任务**不强制补**，由 `guard-check` 报告。
- 需要豁免的任务打 `legacy` 标签：`bd label <id> legacy`。
- 新任务从创建起强制遵守本规范。

## 边界

- `bdg` 是"强制入口"；绕过 `bdg` 直接使用 `bd create/close` 仍可能产生不合规任务，`guard-check` 用于兜底发现。
- 不要用 `bdg` 拦截所有 `bd` 命令（`bd ready/prime/list` 等只读操作不需要强制记录）。

## 硬拦截（可选启用）

默认 `bdg` 是"引导"：AI 仍可直接调 `bd`。若要让写操作**绕不过去**，启用 bd 守卫 wrapper——把 `workspace/bin/` 前置到 PATH，裸 `bd` 命令就会先落到守卫，拦截 `create/close/update/note/comment/delete/import/edit/merge` 等写操作并引导到 bdg；`list/show/ready/query` 等只读操作透明转发真实 bd。

```bash
# 启用（当前会话生效）
source workspace/enable_bd_guard.sh        # macOS / Linux / Git Bash
call workspace\enable_bd_guard.bat          # Windows

# 验证
bd list            # 应正常（只读转发）
bd create test     # 应被拦截并提示走 bdg
```

要持久化，把 `source workspace/enable_bd_guard.sh` 加进 `~/.bashrc`（Windows 用 `setx` 改用户级 PATH，需自行确认）。工具链自身（看板、bdg）会自动绕过 wrapper 调用 npm 全局的真实 bd，不会递归。
