# 视频画面与效果核对指南

## 目的

视频特效学习必须同时回答两件事：作者说了什么，以及画面实际发生了什么。字幕只用于定位案例，不足以证明形状、材质、节奏或修改效果。

## 媒体证据入口

媒体处理统一通过 [`统一媒体工具`](统一媒体工具.md) 执行。每个视频来源先生成 `media_meta.json`，再按时间点抽取关键帧；需要验证动态过程时，导出对应的 `clips/<case_id>.mp4`。元数据和片段用于追溯证据，不会替代实际画面观察。

```bash
python -m workspace.tools.media_cli probe "<video_path>" --output "<source_dir>/media_meta.json"
python -m workspace.tools.media_cli frame "<video_path>" <time> "<evidence_frame>.jpg"
python -m workspace.tools.media_cli cut-video "<video_path>" <start> <end> "clips/<case_id>.mp4"
```


### 1. 音频/字幕

提取作者的判断、步骤、参数和限制，保存时间戳转写。自动转写的专业术语必须标记不确定性。

### 2. 画面帧

在每个重要案例保存：

- 全貌帧：确认场景、角色、镜头和效果用途。
- 问题帧：作者指出问题时的实际画面。
- 修改前帧：记录被修改的原始状态。
- 修改后帧：记录演示或调整后的状态。
- 动态关键帧：前摇、爆发、持续和收尾。
- 工程帧：Inspector、Shader Graph、VFX Graph、Timeline 或节点画面（视频实际展示时）。

### 3. 动态过程

静帧不能替代动态观察。至少记录：

- 出现顺序。
- 运动方向和速度变化。
- 爆发峰值。
- 生命周期和衰减。
- 元素之间的先后关系。
- 接触、命中和环境反馈。

### 4. 效果对照

建立同一时间段的对照记录：

| 时间 | 口述 | 画面 | 可见变化 | 结论 |
|---|---|---|---|---|
|  |  |  |  | 支持 / 部分支持 / 不支持 / 待复核 |

## 抽帧策略

不要只按固定间隔机械抽帧。先通过转写定位案例区间，再在区间内抽取：

1. 案例开始前一帧。
2. 作者描述问题时的一帧。
3. 修改动作完成后的一帧。
4. 效果峰值帧。
5. 效果收尾帧。

操作暂停、参数面板或画面变化不明显时，可提高抽帧密度；动态较快时，应使用局部慢放或更密集帧序列。

## 视觉记录维度

每个案例至少检查：

- 形状：轮廓、宽窄、核心和局部变化。
- 运动：方向、速度、加速度、旋转和衰减。
- 材质：透明度、流动、边缘、噪声、扭曲和高光。
- 颜色：主色、辅助色、亮度峰值和前后统一。
- 节奏：前摇、爆发、持续和收尾。
- 空间：前后、内外、包裹、接触和角色可读性。
- 属性：画面是否真的像火焰、水、冰、雷电或其他目标属性。
- 工程：只记录画面实际展示的组件、节点、参数和资源。

## 结论门槛

- **画面支持**：口述与画面一致，且关键变化有前后帧证据。
- **部分支持**：口述方向成立，但画面或动态证据不完整。
- **不支持**：画面明确与口述相反。
- **待复核**：抽帧不足、视频压缩严重、术语不清或修改前后不可见。

只有“画面支持”或经过 Unity 实验验证的结论，才能升级为稳定知识。仅凭字幕的摘要必须标记为“音频初稿”。

## 文件命名

```text
<资料ID>_<案例ID>_<时间>_<用途>.jpg
```

示例：

```text
SRC-2026-001_CASE-03_00-09-45_problem.jpg
SRC-2026-001_CASE-03_00-10-20_after.jpg
SRC-2026-001_CASE-03_00-10-42_burst.jpg
```
