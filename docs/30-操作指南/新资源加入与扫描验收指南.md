# 新资源加入与扫描验收指南

## 目的

所有新增贴图、模型、材质、Shader、UnityPackage 或其他参考资料，放入本地资源库后，必须先通过资源索引扫描，再进入 Unity 工程制作。

资源库路径：

```text
E:\Unity特效人工智能学习\resource
```

索引输出路径：

```text
E:\Unity特效人工智能学习\workspace\data\resource_index
```

扫描器只读取 `resource`，不会移动、重命名、删除或修改原始文件。

## 一、加入新资源

1. 将新资源复制到 `resource` 下合适的分类目录。
2. 尽量按用途归类，例如：
   - `特效贴图（PNG）/刀光类`
   - `特效贴图（PNG）/序列帧贴图`
   - `y117/新贴图/tbq/mask`
   - `特效模型/600特效模型/UE4特效模型FBX/冰`
   - `特效模型/600特效模型/UE4特效模型FBX/刀光`
3. 不要为了配合索引重命名已有素材，不要把生成文件放回 `resource`。
4. 如果资源来自外部资料，同时保留来源、作者、原始链接和授权说明。
5. 授权不明确的资源可以用于内部学习和本地实验，但不能默认用于公开项目或可分发资产。

## 二、运行增量扫描

打开 Windows CMD，执行：

```cmd
cd /d "E:\Unity特效人工智能学习"

python -m workspace.tools.resource_index.cli scan --root resource --output workspace\data\resource_index --json
```

这条命令是增量扫描：

- 未变化文件：复用已有索引结果。
- 新增文件：提取类型、目录标签、SHA-256、图片元数据和缩略图。
- 修改文件：重新提取元数据并更新记录。
- 删除文件：保留历史记录并标记为 `missing`。
- 损坏或不支持的文件：记录错误，不应中止其他文件的扫描。

扫描期间不要删除、移动或重命名 `resource` 中的文件。

如果需要强制重新计算文件哈希，可以使用：

```cmd
python -m workspace.tools.resource_index.cli scan --root resource --output workspace\data\resource_index --force-hash --json
```

只有在确认索引文件损坏、需要重新校验全部内容或排查重复资源时，才使用 `--force-hash`。

## 三、扫描验收

扫描命令返回后，必须执行统计检查：

```cmd
python -m workspace.tools.resource_index.cli stats --json
```

验收以下项目：

1. 命令退出码为 `0`。
2. `scan_summary.json` 已生成或被更新。
3. SQLite 索引和 JSONL 索引都存在：
   ```text
   workspace\data\resource_index\assets.sqlite3
   workspace\data\resource_index\assets.jsonl
   ```
4. `present` 数量包含刚加入的文件。
5. `errors` 数量没有因为新资源异常增加；若增加，必须查看错误详情。
6. 新增贴图有宽度、高度、模式和通道信息。
7. 新增贴图能在 `thumbnails` 目录找到预览图；无法生成预览时必须记录原因。
8. 新增模型被识别为 `model`；模型几何深度解析属于后续阶段，不能因为当前没有顶点数据就伪造数据。
9. `license_status` 默认是 `unknown`，除非已经完成人工授权审核。
10. 新资源没有被标记为 `missing`。

查询新资源时，可以使用：

```cmd
python -m workspace.tools.resource_index.cli query --type texture --limit 20 --json
python -m workspace.tools.resource_index.cli query --type model --limit 20 --json
python -m workspace.tools.resource_index.cli duplicates --limit 20 --json
```

按目录标签查询示例：

```cmd
python -m workspace.tools.resource_index.cli query --type texture --tag slash --limit 20 --json
python -m workspace.tools.resource_index.cli query --type texture --tag mask --limit 20 --json
python -m workspace.tools.resource_index.cli query --type model --tag ice --limit 20 --json
```

## 四、什么情况算扫描通过

新资源只有同时满足以下条件，才算“已索引”：

- 资源文件仍位于 `resource` 下。
- 扫描命令成功退出。
- 资源在索引查询结果中出现。
- 资源状态为 `present`。
- 类型识别正确，或错误已被明确记录。
- 图片元数据可读取，或存在明确错误记录。
- 缩略图可读取，或存在明确错误记录。
- 授权状态已记录。
- 没有未经说明的重复内容或路径冲突。

只有完成上述检查，才允许把资源复制或引用到 Unity 工程中。

## 四点五、资源类型与处理边界

资源需求不只有贴图和模型。先按下表确定它是“外部输入资产”还是“Unity 工程内生成资产”：

| 类型 | 索引类型/来源 | 找到时的处理 | 未找到时的处理 | Unity 验收重点 |
|---|---|---|---|---|
| 贴图、序列帧、Mask、Noise、Ramp、Normal、HDR | `texture` | 记录尺寸、通道、色彩空间、UV/序列帧信息和 `asset_id`，复制副本后导入 | 占位纯色/渐变/程序纹理，或创建生成任务；生成后重新扫描 | TextureImporter、Alpha、sRGB、压缩、Wrap、Filter、序列帧布局 |
| FBX、OBJ、GLTF、网格、骨骼模型 | `model` | 记录 `asset_id`、hash、来源和模型规格，复制副本后导入 | Unity 内置几何体或程序网格继续逻辑验证，或创建模型生成/获取任务 | 轴向、单位、Pivot、法线、UV、材质槽、动画和 Prefab 引用 |
| `.mat` 材质资产 | `material` | 只作为参考或受控输入；检查 Shader 和依赖贴图，不直接信任外部序列化参数 | 在 Unity 目标 URP 中新建材质，记录 Shader、Blend、ZWrite、ZTest 和依赖 | 材质实例、Shader、纹理引用、混合和深度参数可回读 |
| `.shader`、`.hlsl`、`.compute`、Shader Graph | `shader` | 检查来源、版本、依赖包和渲染管线；复制到工程专用目录 | 用 URP 官方 Shader、Shader Graph 或最小自有 Shader 占位 | 编译无错误、目标管线兼容、参数和 Keyword 可解释 |
| `.unitypackage` | `package` | 不自动解压；确认来源、版本和授权后，在隔离工程试导入 | 以单文件需求记录为缺口，不把压缩包内容当成已验证资产 | 导入清单、依赖包、脚本权限和工程污染范围 |
| PDF、TXT、MD、DOCX、来源说明 | `document` | 作为来源、授权、参数或制作参考，进入知识/资料流程 | 建立资料缺口记录，不伪造来源或参数 | 来源、版本、适用范围和证据定位 |
| ZIP、RAR、7Z、TAR、GZ | `archive` | 只记录包本身；人工确认后在隔离目录解包，再对解包结果重新扫描 | 保留缺口和失败原因，不直接进入 Unity | 解包清单、来源、授权和重新索引结果 |
| Prefab、Scene、Timeline、脚本、Volume、ProjectSettings | Unity 工程资产，不属于 `resource` 原始索引 | 在 Unity 工程内创建或复制，记录工程路径、版本和依赖；必要时写入效果 manifest | 用最小场景、空 Prefab、默认 Timeline 或脚本占位继续验证 | `.meta`、引用完整性、`projects verify`、Pipeline 回读、Play Mode |
| 音频、字体、UI 图集、配置 JSON、外部插件 | 目前通常为 `other` 或需扩展分类 | 先登记格式、来源、授权和运行时依赖，再决定是否加入专用索引 | 用占位音频、默认字体、临时配置或禁用可选功能 | 导入设置、平台兼容、运行时加载、许可证和包依赖 |

`material`、`shader`、`package`、`document`、`archive` 的索引只证明文件存在和可追溯，不证明它们已经适合直接导入 Unity。Prefab、Scene、Timeline 等工程资产则由 Unity 工程本身管理，必须通过 Unity CLI/Pipeline 验证，不能把它们误认为 `resource` 扫描已经验证。


### 命令返回非零退出码

先保留终端输出，不要立即删除索引文件。常见原因包括：

- Python 环境或 Pillow 不可用。
- 输出目录没有写权限。
- SQLite 文件损坏或被其他程序锁定。
- `resource` 路径写错。
- 扫描过程中资源被移动或删除。

确认路径和进程占用后，再重试：

```cmd
python -m workspace.tools.resource_index.cli stats --json
python -m workspace.tools.resource_index.cli scan --root resource --output workspace\data\resource_index --json
```

### 单个资源报错

单个文件错误不等于全量扫描失败。记录以下信息：

- 相对路径
- 文件扩展名
- 错误文本
- 来源和授权状态
- 是否仍要保留为 `reference_only`

不要通过改名或改扩展名掩盖错误。需要修复时，在原文件之外生成处理后的副本，再重新扫描。

### 新资源没有出现在索引

按顺序检查：

1. 文件是否真的位于 `resource` 下。
2. 文件是否为符号链接或位于被忽略的路径。
3. 扫描命令的 `--root` 是否正确。
4. 文件是否在扫描期间被其他程序占用或移动。
5. 是否查看了正确的输出目录。
6. 是否需要重新执行 `--force-hash`。

## 六、进入 Unity 前的授权与兼容性检查

索引通过不代表资源可以公开使用，也不代表资源能直接在 Unity 中正确显示。导入 Unity 前还要确认：

- 来源、作者、原始地址和授权状态。
- PNG/TGA/DDS 的颜色空间、Alpha、压缩和平台兼容性。
- 序列帧的行列数、UV 方向和播放方式。
- FBX 的轴向、单位、法线、Pivot、UV 和材质槽。
- Shader 是否依赖 Built-in、URP、HDRP 或特定插件。
- Unity 版本和目标渲染管线。

外部资料授权不明时，只用于内部学习、检索、转写和分析；不公开传播，不作为可分发项目资产。

## 七、索引未命中时的资源缺口处理

贴图或模型需求没有在结构化索引中命中时，不得直接跳过索引、随意下载或把相似资源当成需求资源。必须先区分“查询未命中”“格式/授权不可用”和“确实缺失”。

### 1. 复核查询

按以下顺序复核：

1. 使用中文、英文和同义词重新查询。
2. 分别按 `type`、目录标签、尺寸和格式查询。
3. 使用向量检索查找视觉相似候选；向量结果只能作为候选排序，不能替代授权和格式检查。
4. 检查是否存在资源但状态为 `restricted`、`reference_only` 或 `unknown`。
5. 检查是否是格式不兼容、图片损坏、模型解析失败或索引输出目录选错。

查询复核仍未得到可用资源，才记录为资源缺口。

### 2. 资源缺口记录

至少记录以下字段，记录可放在对应 Beads 任务、实验记录或资产需求 manifest 中：

```json
{
  "request": "刀光序列帧贴图",
  "asset_type": "texture",
  "query": "slash flipbook transparent",
  "searched": ["structured_index", "vector_index"],
  "result": "not_found",
  "fallback": "placeholder_or_generated",
  "generation_status": "planned",
  "license_status": "unknown",
  "next_action": "generate_local_flipbook"
}
```

`not_found` 只表示当前检索范围没有可用候选，不表示外部世界不存在该资源。不得用一个相似资源的 `asset_id` 冒充原需求。

### 3. 选择处理分支

- **继续验证效果逻辑：** 使用 Unity 内置几何体、纯色材质、默认粒子或程序化形体作为占位，标记 `asset_status: placeholder`、`visual_fidelity: experimental`。
- **需要正式视觉资产：** 创建资产生成任务，或创建经过授权的外部获取任务。
- **已有资源但格式不兼容：** 只在原文件之外生成处理副本，记录转换参数，再重新扫描。
- **授权不明确：** 仅用于内部学习和本地实验，保持 `license_status: unknown` 或 `reference_only`，不得进入公开发布包。
- **生成或获取失败：** 保留失败原因，回退到占位资源，不修改原始 `resource/`。

### 4. 生成或获取后的回流门

任何新生成、转换或获得授权的贴图/模型，都必须重新进入索引流程：

```text
生成或获取到临时目录
→ 检查格式、尺寸、Alpha、UV、法线、拓扑等
→ 记录来源、生成参数或授权信息
→ 放入 resource 或受控的资源输入目录
→ 增量扫描
→ 获得 asset_id、relative_path、sha256、license_status
→ 再复制或导入 Unity
→ 写入 Unity manifest
→ projects verify 和 Pipeline 回读
```

未重新索引的资源不得进入正式 Unity 资产清单。灰盒占位可以继续验证生命周期、形体、节奏、触发和层级，但不能宣称正式视觉资产已经完成。

## 八、跨工程特效摄入完整性门禁

从其他 Unity 工程导入 Prefab 特效时，资源索引通过并不证明 Prefab、材质、贴图、模型和 Shader 已构成可用闭包。使用 `workspace.tools.vfx_source_ingest` 创建来源记录时，必须保留 `--resolve-project-guids`：该工具会生成 `ingest_integrity_report.json`，并将结果写回 `source_manifest.json`。

最小只读检查示例：

```powershell
python -m workspace.tools.vfx_source_ingest `
  --source "<来源工程>/Assets/<特效目录>" `
  --output-dir "workspace/data/vfx_generation/sources/<来源标识>" `
  --source-id "<来源标识>" `
  --title "<特效名称>" `
  --effect-family "<特效族>" `
  --source-unity-project "<来源工程>" `
  --resolve-project-guids
```

`ingest_integrity_report.json` 必须检查以下结论：

- `m_Texture` 槽位：区分真实绑定、合法空槽、无法解析和错误资产类型。任何带 GUID 的 `m_Texture` 无法解析为 Texture 时，摄入命令失败，manifest 状态为 `blocked`。
- Material GUID：检查目标 `Assets` 范围内的重复 Material GUID。存在重复时摄入命令失败，禁止继续把该样本当作依赖闭包完成。
- GUID 类型摘要：分别计数 texture、shader、script、mesh 等引用；这能区分“贴图断链”与“脚本/上下文缺失”。
- Shader `CustomEditor`：记录每个 Shader 声明的编辑器类、来源可用性、目标可用性和复制动作。`needs_manual_dependency` 表示 Inspector 依赖未满足，不应伪装成运行时贴图或 Shader 丢失。

### 受控 ShaderGUI 复制

默认不复制任何 `CustomEditor` 对应的脚本或 DLL。只有已确认许可、明确指定源/目标路径时，才创建策略文件并使用 `--copy-shader-gui-dependencies`。策略格式如下：

```json
{
  "schema_version": "vfx_shader_gui_policy.v1",
  "dependencies": {
    "Example.Editor.CustomGui": {
      "allowed": true,
      "license_status": "local_reference_only",
      "source_path": "Assets/Editor/ExampleGui",
      "target_path": "Assets/Editor/ExampleGui"
    }
  }
}
```

调用时追加：

```powershell
--target-unity-project "<目标工程>" `
--copy-assets `
--shader-gui-policy "<策略文件>.json" `
--copy-shader-gui-dependencies
```

策略中缺少 `allowed: true`、许可状态为 `unknown` / `blocked`、路径不在项目 `Assets` 内，或目标路径已存在时，工具不会复制，报告会保留明确原因。ShaderGUI 只影响 Inspector 编辑体验；Prefab、Material、Texture、Mesh、Shader 的运行时闭包仍必须分别通过 GUID 检查、Unity 编译和 Play Mode 画面验证。

## 九、日常最短流程

以后每次加入素材，至少执行：

```cmd
cd /d "E:\Unity特效人工智能学习"
python -m workspace.tools.resource_index.cli scan --root resource --output workspace\data\resource_index --json
python -m workspace.tools.resource_index.cli stats --json
```

然后用 `query` 确认新资源存在，再进入 Unity。不要跳过扫描直接从资源目录手工挑选并导入。
