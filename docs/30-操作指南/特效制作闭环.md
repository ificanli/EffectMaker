# 特效制作闭环

## 1. 明确需求

填写需求模板，至少确定用途、风格、镜头距离、持续时间、目标平台和性能限制。

## 2. 视觉拆解

将效果拆成形状、运动、材质、颜色、节奏、空间层次和环境交互。明确核心视觉，不先堆细节。

## 3. 技术选型

根据技术选型参考确定 Particle System、VFX Graph、Mesh、Shader、Trail、Timeline 或脚本事件的组合，并记录选择原因。

## 4. 灰盒制作

先只实现主体轮廓、规模、方向、生命周期和爆发节奏。此阶段不追求纹理和复杂细节。

## 5. Unity 验证

先用 Unity CLI 检查项目、Editor 版本和认证状态，再执行构建、测试或注册的 Editor 命令：

```bash
unity projects verify "<project-path>" --format json
unity editors --format json
unity doctor
```

CLI 不覆盖的实时层级、组件、运行状态、Console 或截图操作，再通过 Unity MCP 或 Editor 脚本完成。无论使用哪种工具，都必须确认对象、材质、粒子、时间和触发逻辑实际运行并保存。

## 6. 第一轮评估

只检查识别度、轮廓、动态节奏和镜头适配。记录明确问题，不要同时修改所有参数。

## 7. 细节制作

按优先级加入辅助粒子、噪声、流动、溶解、拖尾、碎片、地面反馈和环境光。

## 8. 第二轮评估

检查材质可信度、空间层次、场景融合、亮度层级和边缘问题。

## 9. 工程化

整理层级、命名、参数、材质引用和预制体结构，确保效果可独立复用。

## 10. 性能检查

记录粒子数量、Overdraw、Shader、后处理和目标设备表现，处理不必要的透明叠加和高成本效果。

## 11. 保存和复盘

保存场景、预制体和相关资源，填写复盘模板。失败版本和未解决问题也必须记录。任何 Unity CLI、Pipeline、MCP 或 Editor 错误，必须按 [错误沉淀与预防规范](错误沉淀与预防规范.md) 记录原始命令、根因、修复、复验和预防措施；未完成记录不能关闭任务或升级实验状态。

## 每轮迭代限制

每一轮优先只解决一类问题：

- 轮廓问题。
- 节奏问题。
- 材质问题。
- 层次问题。
- 场景融合问题。
- 性能问题。

这样才能判断改动是否真正有效。
