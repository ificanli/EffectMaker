# 双管道学习架构

> 审美类资料和制作类资料需要不同的处理方式。本文档定义两条管道的分工、流程差异和交叉验证方式。

## 为什么要分两条管道

两类资料回答的是完全不同的问题：

| | 审美类 | 制作类 |
|---|---|---|
| 典型来源 | 作业点评、作品赏析、优秀参考视频 | 分步教程、案例复刻、公开课录屏 |
| 回答的问题 | 好不好、哪里不好、先改什么 | 用什么技术、什么参数、什么顺序 |
| 核心产物 | 判断规则、检查清单、失败模式库 | 步骤模板、参数范围、技术组合 |
| 证据重点 | 修改前后对比、动态节奏、空间关系 | 操作顺序、Inspector 参数、节点连接 |
| 是否需要 MCP | 不直接需要 | 必须在 Unity 中复现 |
| 沉淀位置 | `knowledge/cards/AESTHETIC-*` | `knowledge/cards/CRAFT-*` |

把两类资料混在一条管道里处理，会导致：判断规则缺少可执行步骤，或者操作步骤缺少质量标准。

## 管道 A：审美类

### 目标

积累"看得出问题"的判断力，形成可复用的评审顺序和失败模式库。

### 流程

```text
下载
→ 统一媒体工具读取元数据（media_meta.json）
→ 音频提取与转写（定位案例边界）
→ 按案例抽帧与导出片段（问题帧 + 修改前 + 修改后）
→ 视觉核对（口述 vs 画面）
→ 提炼判断规则
→ 跨来源交叉验证
→ 沉淀为检查清单
```

### 抽帧策略

优先抓"对比"，而不是"过程"：

1. 作者指出问题时的画面。
2. 修改前的原始状态。
3. 修改后的调整状态。
4. 动态峰值（爆发/最亮/最大范围）。
5. 收尾状态。

### 提取重点

- 作者指出了什么问题。
- 问题属于哪个维度（形状/运动/材质/颜色/节奏/空间/属性）。
- 判断依据是什么。
- 修改方向是什么。
- 这条判断能否迁移到其他效果类型。

### 产物

- 失败模式条目：问题描述 + 视觉表现 + 分类 + 改进方向 + 证据时间戳。
- 评审优先级：先看什么、后看什么。
- 检查清单：可直接用于自己作品的自查项。
- 媒体证据：`media_meta.json`、关键帧 JPG，以及必要时的 `clips/<case_id>.mp4`。

### 不做的事

- 不记录具体参数值（点评视频通常不展示 Inspector）。
- 不推断制作步骤。
- 不把个人偏好当作通用规则。

## 管道 B：制作类

### 目标

积累"做得出来"的操作力，形成可执行的步骤模板和参数范围。

### 流程

```text
下载
→ 统一媒体工具读取元数据（media_meta.json）
→ 音频提取、分段与转写（定位步骤边界）
→ 按步骤抽帧与导出片段（操作前 + 操作中 + 操作后）
→ 视觉核对（步骤 vs 结果）
→ 提取可执行步骤和参数
→ 在 Unity 中复现（MCP）
→ 验证结果是否一致
→ 沉淀为制作模板
```

### 抽帧策略

优先抓"因果"，而不是"对比"：

1. 操作前的场景/资源状态。
2. Inspector 或节点面板画面（参数可读时）。
3. 操作执行瞬间。
4. 操作后的视觉变化。
5. 阶段性成果。

### 提取重点

- 使用了什么技术（Particle System / VFX Graph / Shader / Mesh / Timeline）。
- 关键参数及其数值范围。
- 操作顺序和依赖关系。
- 哪些步骤是必须的，哪些是风格化选择。
- 失败尝试和修正方式。
- 版本、管线和插件依赖。

### 产物

- 步骤模板：有序操作列表 + 每步的预期结果。
- 参数表：参数名 + 示例值 + 视觉影响 + 证据位置。
- 技术组合：这个效果由哪些技术叠加而成。
- Unity 复现记录：MCP 操作日志 + 结果截图 + 差异说明。
- 媒体证据：`media_meta.json`、步骤关键帧和能回放操作过程的 `clips/<case_id>.mp4`。

### 不做的事

- 不把画面中看不清的参数写成确定值。
- 不跳过复现直接采纳步骤。
- 不忽略版本差异。

## 交叉验证

两条管道的产物必须互相检验：

### 审美规则 × 制作实践

用管道 B 的复现结果，验证管道 A 的判断规则是否真的有效。

例：审美规则说"能量衰减不能只调 Alpha"。在 Unity 中做两个版本：
- A 版：只调 Alpha
- B 版：同时调数量、长度、尺寸、频率

如果 B 版在相同镜头下明显更好，规则成立；否则需要补充适用条件。

### 跨来源验证

同一条规则如果只出现在一个作者的资料中，标记为"单来源观察"。出现在两个以上独立来源，且都有画面支持，才能升级为"通用规则"。

### 状态流转

```text
单来源观察（single-source）
→ 多来源确认（cross-verified）
→ Unity 实验支持（experiment-backed）
→ 项目规范（adopted）
```

只有 `adopted` 状态的规则可以写入 `docs/20-参考/` 下的稳定文档。

## 资料分类判断

收到新资料时，先判断类型：

| 特征 | 判定 |
|---|---|
| 标题含"点评""赏析""分析""复盘" | 审美类 |
| 标题含"教程""制作""实战""复刻""从零" | 制作类 |
| 画面主要是播放和暂停成品 | 审美类 |
| 画面主要是编辑器操作 | 制作类 |
| 同时包含两者 | 按主要时长归类，并在 source.md 标注混合 |

混合型资料按段落拆分，分别进入两条管道。

## 目录规范

```text
knowledge/
  sources/
    <SRC-ID>/                    # 单集或系列
      source.md                  # 来源登记（标注管道类型）
      index.md                   # 系列内各集处理状态
      videos/                    # 视频文件
      transcripts/               # 转写
      evidence/                  # 视觉证据
      review_*.md                # 分段核对记录
  cards/
    AESTHETIC-*.md               # 审美判断规则
    CRAFT-*.md                   # 制作步骤模板
  experiments/
    EXP-*.md                     # Unity 验证实验
  index.md                       # 全库追踪
```
