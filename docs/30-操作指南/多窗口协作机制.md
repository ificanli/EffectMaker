# 多窗口协作机制

> 当多个 ZCode 窗口同时学习不同资料时，用 **Beads (bd)** 做任务协调中枢，避免重复劳动和冲突。
>
> 历史版本用 `workspace/boards/` 的 Markdown 看板 + 追加式日志，已于 2026-08-23 迁移到 bd。旧文件保留作历史记录，不再更新。

## 核心原则

1. **bd 即状态**：所有任务的认领、进度、阻塞都记在 bd 数据库（`.beads/`），不依赖内存或对话上下文。
2. **原子认领**：`bd ready --claim` 由数据库保证原子性，多窗口同时抢任务先到先得，不会撞车。
3. **一个任务一个 bead**：一集视频的一个管道处理 = 一个 bead。不要把整个系列当一个任务领走。
4. **可恢复**：窗口崩溃后任务停在 `in_progress`，其他窗口用 `bd stale` 扫出僵尸任务后释放接管。

## 窗口标识

每个窗口启动时确定自己的 ID，格式 `W-<日期>-<序号>`（例：`W-0823-01`）。所有 bd 命令通过环境变量带上身份：

```bash
export BEADS_ACTOR=W-0823-01
```

或每条命令加 `--actor W-0823-01`。认领后 assignee 就是窗口 ID，其他窗口能看到是谁在做。

## 任务组织

- 每个资料源（SRC-ID）是一个 **epic**，例：`vfx-mp7` = SRC-2026-SERIES-001。
- 每集/每个知识点是 epic 下的**子任务**，例：`vfx-mp7.1` = 第02集。
- 管道类型用**标签**：`审美` / `制作` / `混合`。
- 优先级 P0–P3 与原 BACKLOG 一致。

## 任务认领流程

### 1. 看有什么可做

```bash
bd ready --exclude-type epic          # 所有就绪任务（无阻塞、未被认领）
bd ready --exclude-type epic -l 审美  # 只看审美管道
bd blocked                            # 看哪些被阻塞
```

### 2. 认领（原子，不需要再检查冲突）

```bash
bd ready --claim --exclude-type epic --json           # 自动认领优先级最高的就绪任务
bd ready --claim --exclude-type epic -l 制作 --json   # 只认领制作管道的任务
bd update vfx-mp7.1 --claim                           # 认领指定任务
```

认领成功任务变为 `in_progress` 且 assignee 是自己；返回空说明没抢到，换下一个。

### 3. 记录进度

每完成一个阶段（转写/抽帧/核对/卡片），追加评论：

```bash
bd comment vfx-mp7.1 "转写完成，输出 knowledge/sources/SRC-2026-SERIES-001/ep02/transcript.md"
bd comment vfx-mp7.1 "抽帧完成，42 帧"
```

### 4. 完成 / 阻塞 / 放弃

```bash
bd close vfx-mp7.1 --reason "完成，产出 CARD-2026-002"   # 完成
bd update vfx-mp7.1 --status blocked                     # 阻塞（同时 comment 写原因）
bd update vfx-mp7.1 --status open --assignee ""          # 放弃，释放回队列
```

## 僵尸任务接管

窗口崩溃后任务会停留在 `in_progress`。每个窗口**开工前先扫一遍**：

```bash
bd stale          # 列出长时间未更新的 in_progress 任务
```

超过 **2 小时**无更新的任务视为失效，可以接管：

```bash
bd update <id> --status open --assignee ""   # 释放
bd update <id> --claim                        # 自己认领
bd comment <id> "超时接管自 W-0823-01"
```

## 任务粒度

一个任务 = 一集视频的一个管道处理。推荐拆分：

| 粒度 | 说明 | 预计时长 |
|---|---|---|
| 单集完整处理 | 下载→转写→抽帧→核对→沉淀 | 1–3 小时 |
| 单集单阶段 | 只做转写或只做视觉核对 | 20–60 分钟 |
| 批量下载 | 一个系列的下载任务 | 后台，不占用窗口 |

范围较大的占位任务（如"第05-10集"）认领后应先拆分：

```bash
bd create "第05集" --parent vfx-mp7 -p 1 -l 审美
bd create "第06集" --parent vfx-mp7 -p 1 -l 审美
bd close vfx-mp7.4 --reason "已拆分为单集任务"
```

## 分工建议

按管道分工（推荐，与双管道架构一致）：

- 审美窗口：`bd ready --claim -l 审美 --exclude-type epic --json`
- 制作窗口：`bd ready --claim -l 制作 --exclude-type epic --json`
- 交叉验证 + Unity 实验窗口：不领队列任务，按需建新任务

各窗口只要都用 `--claim`，即使标签重叠也不会撞车。

## 共享文件写入规则

bd 只解决"谁做什么"。文件层面的规则不变：

### 独占文件

认领了任务的窗口独占对应文件：

- `knowledge/sources/<SRC-ID>/` 下的所有文件
- `workspace/progress/<SRC-ID>.md`

### 需要协调的共享文件

修改 `knowledge/index.md`、`docs/` 文档、`knowledge/cards/` 共享卡片前，先建一个临时 bead 声明：

```bash
bd q "编辑 knowledge/index.md 添加ep02追踪行" && bd update <返回的id> --claim
# 改完：
bd close <id> --reason "已完成编辑"
```

其他窗口看到某文件有 `in_progress` 的编辑任务时（`bd list --status in_progress`），等待或先做别的。

## 发现新任务

处理过程中发现的新工作（新阻塞、待补充的知识点、Unity 实验想法）随手记录，不要放在脑子里：

```bash
bd create "ep02 提到的溶解贴图制作方法需要单独实验" -p 2 -l 制作 --deps discovered-from:vfx-mp7.1
```

## 启动检查清单

新窗口开始工作前：

- [ ] 确定窗口 ID，`export BEADS_ACTOR=W-<日期>-<序号>`
- [ ] `bd stale` 检查僵尸任务，超时的释放接管
- [ ] `bd ready --exclude-type epic` 了解当前队列
- [ ] `bd ready --claim ... --json` 认领任务
- [ ] 读 `docs/30-操作指南/单集视频学习SOP.md` 确认流程
- [ ] 读 `docs/30-操作指南/双管道学习架构.md` 确认管道类型

## 结束检查清单

窗口结束工作前：

- [ ] `bd close` 或释放手上的任务，不要留着 `in_progress` 下线
- [ ] 进度和产出用 `bd comment` 记在任务上
- [ ] 发现的新工作用 `bd create` 建好
- [ ] 更新 `workspace/progress/<SRC-ID>.md`

## 与主流程的关系

多窗口协作不改变学习流程本身。每个窗口仍然：

1. 按 [单集视频学习SOP](单集视频学习SOP.md) 处理单集。
2. 按 [双管道学习架构](双管道学习架构.md) 判断管道类型。
3. 按 [视频画面与效果核对指南](视频画面与效果核对指南.md) 做视觉核对。

协作机制只解决"谁做什么"和"做到哪了"。
