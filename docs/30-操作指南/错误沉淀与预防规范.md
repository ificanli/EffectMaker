# 错误沉淀与预防规范

## 目的

所有制作过程中的错误都必须转化为可检索、可复用的工程知识，避免下一次重复犯同一类错误。错误记录不是事后可选的总结，而是 Unity CLI、Pipeline、MCP 和 Editor 操作的完成条件之一。

## 适用范围

- Unity CLI 命令失败、退出码异常或返回部分成功。
- Unity Pipeline/Editor 命令失败、连接中断、编译或域重载问题。
- Unity MCP 工具调用失败、参数不兼容或能力不支持。
- 资源导入、包解析、构建、测试、运行和保存失败。
- 视觉效果、时序、空间关系、性能或兼容性不符合目标。
- 因路径、编码、版本、许可证、权限、网络或外部资源导致的阻塞。

## 强制流程

每次出现错误后，按顺序执行：

1. 保留原始错误：命令、参数、退出码、完整错误文本、时间和工程路径。
2. 判断影响范围：是否修改了工程，是否产生半成品，是否污染了场景或资源。
3. 定位根因：区分表象、直接原因和系统性原因，不把猜测写成结论。
4. 修复或隔离：优先选择可逆修复；涉及许可证、账号、外部服务时停止并请求授权。
5. 重新验证：使用同一工具或独立工具确认错误已消失，并记录新的输出。
6. 提炼预防措施：形成命令前置检查、路径约束、版本约束、参数校验或工具选择规则。
7. 建立关联：在 Beads 任务中追加评论；跨任务经验使用 `bd remember`；具体错误保存在本目录的错误日志中。

## 统一记录字段

每条错误至少包含：

- `error_id`：稳定编号，例如 `ERR-UNITY-001`。
- `date`：发生日期。
- `task`：Beads 任务 ID或实验 ID。
- `project`：工程绝对路径或项目名。
- `unity_version`：Unity Editor 版本。
- `tool`：`unity-cli`、`pipeline`、`mcp`、`editor` 或其他。
- `command`：完整可复现命令或工具调用。
- `exit_code`：退出码；无退出码则写 `n/a`。
- `symptom`：用户或工具看到的现象。
- `raw_error`：原始错误文本和日志路径。
- `root_cause`：已确认的根因；未确认写明 `unknown`。
- `impact`：对场景、资源、任务和验证结论的影响。
- `fix`：采取的修复动作。
- `verification`：修复后的验证命令和结果。
- `prevention`：下次执行前必须采取的措施。
- `status`：`open`、`mitigated`、`verified` 或 `wont-fix`。

## 开工前检查

任何 Unity 制作任务开始前，先检查：

```bash
unity --version
unity doctor
unity projects verify "<project-path>" --format json
unity projects info "<project-path>" --format json
```

此外必须：

- 检索本文件和 `workspace/progress/ERROR_LOG.md` 中与工程版本、路径、工具和任务主题相关的错误。
- 确认工程路径尽量使用 ASCII；如果路径包含中文，先做路径兼容性检查。
- 确认 Pipeline/MCP 目标工程和端口，不使用旧项目的状态文件。
- 确认包解析完成、Editor 状态为 `ready`、没有编译或域重载。
- 记录当前场景和工作区状态，再执行写操作。

## 完成判定

出现错误但没有记录、没有根因分析或没有复验，任务不能关闭，实验不能从 `planned`/`experimental` 升级为 `verified`。

错误已修复不代表原始失败可以删除。原始错误、修复过程和预防规则必须保留，以便未来判断相同症状是否由同一根因造成。

## 当前首批案例

- `ERR-UNITY-001`：中文工程路径触发 Unity 6 程序集扫描的非法字节序列；预防：Unity 工程优先使用 ASCII 路径。
- `ERR-UNITY-002`：Git Bash 将 `/VFX_Verification/...` 改写为 Windows 文件路径；预防：Pipeline 对象操作优先使用 `GlobalObjectId`，不要把层级路径作为以斜杠开头的 shell 参数。
- `ERR-UNITY-003`：将 Pipeline 的 `read_console` 当作命令调用；预防：每次先用 `unity command --query` 获取当前工程实际命令列表。
- `ERR-UNITY-004`：新增脚本或包编译期间立即查询命令，连接到旧端口或命令未注册；预防：先轮询 `editor_status`，确认 `compiling=false`、`domainReloadInProgress=false`、`status=ready`。
- `ERR-UNITY-005`：把 2022.3 工程误当作 Unity 6 工程安装 Pipeline；预防：先执行 `unity projects info`，确认版本满足包要求。
- `ERR-UNITY-006`：将资料整理和低密度抽帧误判为 Unity 实验完成；预防：没有 Editor/Pipeline 运行证据不得标记 `verified`。
