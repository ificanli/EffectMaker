# 资料投喂与吸收模型

## 核心目标

资料的价值不在于被保存或被模型读过，而在于能否转化为经过证据支持、可以复现、适用于当前 Unity 环境的特效决策和制作能力。

```text
资料 → 多模态证据 → 知识 → 实践 → 沉淀
```

## 多模态证据原则

对于视频特效资料，字幕或语音只能回答“作者说了什么”，不能证明“画面实际展示了什么”。有效吸收必须把以下证据对齐到同一时间段：

1. **语音/字幕**：作者的判断、步骤和解释。
2. **画面帧**：实际效果的形状、颜色、构图、空间关系和材质表现。
3. **动态对照**：效果出现、变化、爆发、衰减和收尾的时间过程。
4. **前后版本**：修改前后或不同参数版本的可见差异。
5. **工程证据**：Inspector、Shader Graph、VFX Graph、Prefab、日志和性能数据（视频展示时才可记录，未展示不能臆测）。

只有字幕、没有画面核对的内容，状态最多为“音频初稿”，不能作为已提取的视觉结论。

## 五层对象

### 资料

原始输入，包括特效源文件、UnityPackage、教学视频、文章、官方文档、论文、图片、参考项目和自主检索结果。

资料必须有来源和获取记录。未经授权的内容只记录引用信息，不擅自复制或传播。

### 证据

资料中可以定位和复查的内容：文章章节、视频时间戳、源文件路径、Prefab 层级、Inspector 参数、Shader 节点、代码片段、截图、日志或性能数据。

没有证据位置的陈述只能标记为推测。

### 知识

从证据中提炼出的规则、步骤、参数关系、技术选择、适用条件和限制。知识必须写清“在什么环境、对什么问题、为什么有效”。

### 实践

在 Unity、MCP 或独立实验环境中对知识进行最小验证。实践结果包括成功、失败、部分成立和无法验证，不能为了得到结论而忽略失败。

### 沉淀

经过验证且具有复用价值的结果，进入技术选型参考、教程、Shader/材质模板、Prefab、效果复盘或 MCP 操作经验库。

## 不同资料的吸收方式

### 特效源文件

重点吸收结构和决策，而不是只看最终效果：

1. 确认 Unity 版本、渲染管线、插件和外部依赖。
2. 检查授权、目录结构、Prefab、材质、纹理、网格、Shader、VFX Graph 和脚本。
3. 按功能拆分核心、主体、细节、环境和控制逻辑。
4. 记录关键参数及其对视觉结果的影响。
5. 在隔离测试场景中验证一个模块，再判断是否可迁移。

### 教学视频

视频必须按时间戳切片，并同时观察声音和画面：

- 目标和最终效果：保存代表性画面帧，记录效果整体用途。
- 场景或资源准备：记录画面中实际出现的对象、材质和环境。
- 关键制作步骤：对齐讲解时间和画面变化，确认操作确实导致了结果变化。
- 参数调整过程：记录调整前帧、调整后帧和可见差异；只记录画面展示过的参数。
- 失败尝试和修正：保留前后对照，不只总结最后结果。
- 动态表现：记录前摇、爆发、持续、收尾、方向、速度和衰减。
- 版本、插件和限制：从画面、字幕或页面信息中确认，未知项明确标记。

最低画面证据要求：每个重要案例至少保存一个代表帧；涉及修改或动态变化的案例，至少保存修改前、修改后和一个关键时间点。只写“讲了如何制作火焰”或只保存字幕，不算有效吸收。

### 画面和效果对照

对视频中出现的效果，必须建立“口述结论 ↔ 画面证据”表：

| 时间段 | 作者说了什么 | 画面实际显示什么 | 前后/动态差异 | 证据文件 | 可信度 |
|---|---|---|---|---|---|
|  |  |  |  |  |  |

画面无法确认、抽帧不足或视频压缩导致细节不可辨认时，结论必须标记为“待复核”，不能用字幕推断纹理、节点或参数。

### 美术资产制作文章

提取问题、约束、方案、参数关系、适用条件、证据和限制。优先区分作者的事实描述、经验判断和没有实验支持的观点。

### 自主检索资料

记录检索关键词、检索日期、来源范围、筛选理由和交叉验证结果。优先使用官方文档、源码、作者原始发布和有可复现步骤的资料。

## 职责边界

- AI：整理资料、定位证据、提炼假设、设计小实验、比较结果和维护索引。
- 用户：提供目标、授权判断、审美方向、优先级和最终采纳决策。
- Unity/MCP：执行场景和资源操作，提供运行结果、日志和参数状态。
- 知识库：保存可追溯的结论、限制和验证关系。

## 采纳原则

资料中的方法不能因为表达清晰或效果漂亮就直接升级为项目规范。至少满足：来源可追溯、适用环境明确、核心结论有证据、已经完成最小验证，或明确记录了无法验证的原因。
