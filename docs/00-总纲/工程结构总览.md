# 工程结构总览

## 目的

这份文档定义仓库级目录边界和放置原则，用来回答三个问题：

1. 新内容应该放在哪里。
2. 哪些目录是主线内容，哪些目录只是派生物或临时物。
3. 发生结构调整时，哪些入口文件需要同步更新。

当前的主工程路由和版本状态，见 [Unity 制作工程进度](../../workspace/progress/UNITY_PROJECT_INDEX.md)。

## 目录总览

```text
E:/Unity特效人工智能学习
├─ UnityDemo/          Unity 项目源文件
├─ workspace/          支撑工具、派生数据、进度、验证沙箱
├─ knowledge/          资料来源、卡片、实验、证据链
├─ docs/               稳定原则、操作指南、模板和总纲
├─ resource/           本地原始资源库
├─ .beads/             任务追踪数据
├─ .codex/             Codex 本地配置
└─ .agents/ .claude/   其他协作工具的本地配置
```

## 目录职责

### `UnityDemo/`

Unity 项目本体，只放 Unity 源文件、场景、包清单和项目设置。

- `EffectDemo6.0/` 是当前主工程。
- `EffectDemo/` 是 Unity 2022 兼容工程；默认用于旧内容对照，任务明确指定时也承接 Trains 源特效摄入、材质时间线和 WebGL 动态训练复核。它不替代 Unity 6 主制作工程。

不要把分析脚本、知识文档、临时网页或生成索引放进这里。

### `workspace/`

放支撑制作流程的代码和运行态数据。

- `tools/`：媒体处理、索引、验证、服务脚本。
- `data/`：可重建的索引、缓存、实验输出。
- `progress/`：状态、阻塞、验收和工程路由。
- `tests/`：工具层回归和契约测试。
- `unity-verification/`：独立的最小验证工程。
- `previews/`：本地 HTML 预览页和人工复核页面，默认不作为长期知识沉淀。

### `knowledge/`

放外部资料到内部知识的转化结果。

- `sources/`：来源登记、字幕、抽帧、视觉复核和素材结构说明。
- `cards/`：经过验证后可复用的规则和结论。
- `experiments/`：Unity 或离线工具验证记录。
- `inbox/`：待处理或待筛选的入口。

### `docs/`

放稳定、可长期引用的说明文档。

- `00-总纲/`：仓库级约定、路线图和总览。
- `10-解释/`：概念、边界和原则。
- `20-参考/`：参考标准、规范和术语。
- `30-操作指南/`：可执行流程和操作步骤。
- `40-教程/`：示例教程和入门路径。
- `90-模板/`：复盘、需求和记录模板。

### `resource/`

本地原始资源库。这里的文件不因为在仓库里就自动具备可公开分发授权。

### 根目录

根目录只保留仓库级入口、配置和少量必须文件。

- 适合保留：`README.md`、`AGENTS.md`、`CLAUDE.md`、`.gitignore`
- 不适合保留：临时 HTML、一次性脚本、导出物、调试截图

## 放置原则

- 稳定的仓库级规则，放到 `docs/00-总纲/`。
- 可执行步骤，放到 `docs/30-操作指南/`。
- 当前工程路由，放到 `workspace/progress/UNITY_PROJECT_INDEX.md`。
- 可重建数据，放到 `workspace/data/`。
- 新脚本先放到 `workspace/tools/`，再按职责细分子目录。
- 视觉证据和资料记录，放到 `knowledge/`。
- 临时物要么进入明确的工作目录，要么进入 `.gitignore`，不要留在根目录。

## 提交边界

### `source of truth`

长期可信的源内容，应该提交并被文档引用。

- Unity 项目源文件、场景、材质、Shader、配置和 `.meta`
- 稳定文档、规范、模板和知识卡片
- 资料来源登记、实验记录和可追溯结论

### `evidence`

能支撑结论的证据，可以提交，但必须有上下文。

- 截图、manifest、日志摘要、参数记录
- 视觉核对记录、实验验收结果
- 工具输出的摘要或索引报告

证据文件必须能回答：来源是什么、验证了什么、适用范围是什么。

### `generated but rebuildable`

可重建的生成物，默认放在 `workspace/data/`。

- 资源索引数据库
- 向量索引
- 缩略图
- 中间 JSONL
- 批处理缓存

这类文件是否提交取决于复现成本和协作价值。不能只因为本地存在就提交。

### `local only`

只用于本机运行、下载、预览或调试，默认不提交。

- 下载的视频、音频和切片
- 本地原始资源库 `resource/`
- 临时 HTML 预览页
- Unity `Library/`、`Temp/`、`Logs/`
- 模型缓存、RAG 缓存、临时服务输出

## 预览页约定

临时 HTML 预览和单帧复核页统一放到 `workspace/previews/`。

- 需要长期保留的视觉结论，写入 `knowledge/` 或 `docs/`，不要只留在 HTML 页面里。
- 需要支撑实验的截图和 manifest，放到对应实验或 Unity 资产证据目录。
- 临时预览页默认进 `.gitignore`，只有明确用于复现流程时才提交。

## 工具拆分阈值

`workspace/tools/` 可以容纳少量一次性脚本，但达到以下任一条件时应拆入子目录：

- 被两个以上任务复用。
- 有独立 CLI 参数。
- 有测试文件。
- 会读写状态文件。
- 依赖第三方模型、索引或长流程缓存。

推荐方向：

```text
workspace/tools/
├─ media/
├─ resource_index/
├─ resource_vectors/
├─ model_index/
├─ unity/
├─ review/
├─ boards/
└─ beads/
```

拆分时优先迁移入口和测试，避免只移动源码导致历史命令失效。

## 维护规则

1. 新增一级目录前，必须先更新本文件，说明目录职责、是否可重建、是否允许提交。
2. 如果目录职责会长期被引用，就写入本文件。
3. 如果只是当前工程状态，就写入 `workspace/progress/UNITY_PROJECT_INDEX.md`。
4. 如果目录里出现大量“fix1”“temp”“new”“test”之类后缀，优先收口成稳定子目录。
5. 结构调整后，至少同步更新 `README.md`、`docs/README.md` 和相关进度文档的入口。

## 结构调整检查清单

每次目录结构调整后，至少检查：

- `README.md` 是否保留正确入口。
- `docs/README.md` 是否保留正确入口。
- 本文件是否更新目录职责和放置原则。
- `.gitignore` 是否覆盖新增的本地生成物。
- `workspace/progress/UNITY_PROJECT_INDEX.md` 是否仍准确。
- 新增长期目录是否有 README 或等价入口说明。
- 是否误把本地素材、缓存、下载媒体或临时预览页放进根目录。
