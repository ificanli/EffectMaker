# 2026-09-07 VFX 生成能力评估

## 结论

近期可行目标是：制作教程提供方法，已有 Prefab 提供资产和结构，规划器选择并调整可验证的制作操作，Unity 产出可编辑候选，再依据动态画面迭代。限定到少数特效类型、明确风格和可控参数时，这条工程路线具有可行性。

当前实现尚不能证明能够稳定生成合格成品。继续增加同一模板的候选、窄轴模型数量或训练轮数，不足以填补实际制作控制和整体质量监督的缺口。现有证据不足以给出统计意义上的成功概率；下列“可能性”是工程判断，不是模型评测结果。

| 目标 | 当前判断 | 达成条件 |
|---|---|---|
| 从 Prompt 生成限定类型、可编辑、可调整的特效候选 | 可行，但当前未完成 | Prompt 改变真实参数；材质/资产正确执行；动态验证可靠 |
| 较稳定地产出专业质量的少数类型特效 | 有条件可行，缺少成功率证据 | 完整教程复现、来源独立的正负样本、整体质量评估和独立 Prompt 回归 |
| 用现有数据从零训练覆盖所有特效族及 Mesh/Texture/Shader 的统一生成网络 | 近期可能性低 | 数据规模、表达统一、语义配对、算力与评测均需显著提升 |

采用已有模型承担语义规划和视觉分析，再训练本项目的结构、资产匹配、参数规划和偏好模块，比从零训练统一资产模型更符合当前条件。工程工具和模型训练应分别验收。

## 实际证据

### Prompt 到执行存在断链

2026-09-07 实测，同一雷电 ProcedureSpec、同一 seed=123，分别输入“风格化蓝色横向短促闪电”和“风格化红色纵向持续闪电”：

- graph_id 不同。
- nodes、components 和 asset_bindings 完全相同。
- 粒子颜色仍为流程文件中的蓝白，旋转仍为约 1.5708，寿命仍为 0.14/0.16 秒。

说明原实现只将部分 Prompt 词写入计划元数据。判定控制生效必须比较可执行字段、Unity 回读和画面，不能比较 ID 或自然语言说明。

### 教程监督覆盖仍很小

现场库中共有 2 条 ProcedureSpec：1 条来自历史烟花技术实验，1 条来自《雷之呼吸 03 闪电制作》的部分字幕和视频片段。目标工程完整复现标记为 0，正式 Planner SFT 样本为 0。

烟花记录不能当成已学会完整教程的证据：来源说明缺少运动方向和完整空间关系，甚至明确没有外部贴图，而后来流程中增加的贴图语义仍是项目推断。雷电记录中的 step_005、step_009 是人工编写的工程参数假设，不能与教程原始数值合并为事实。

需要继续学习完整制作教程，重点记录操作前后、对象与模块、Shader 输入、贴图通道、空间坐标、曲线和时序。字幕与截图用于定位和核对；过程复现及动态对照用于验证。

### 真实梯度训练存在，但作用范围有限

雷电 Pulse 模型的 metrics.json 显示 AdamW、300 epochs、pairwise loss，训练/验证/测试分别为 4/2/2 对。三个分区 pair_accuracy=1.0 只说明少量受控对照上能够区分该轴；测试集只有 2 对，无法据此推断开放 Prompt 的成品成功率。

vfx_controller_r001 目录只有 training_preflight.json，sft_example_count=0、weight_written=false。ProcedureSpec 生成器和资产路由器仍是规则代码，没有训练出的通用制作 Planner。

### Shader 与验证存在误判风险

- 属性名、路径名含 dissolve/flow/emission 只是候选特征，不证明对应参数已正确配置和驱动。
- 同一 Shader 或材质可合法服务多层，不能仅因复用就认定错误。
- 不是所有主体都必须包含溶解或 UV 流动；具体要求应来自视觉目标和已核对的制作方案。
- Particle Vertex Streams 的排列顺序会影响通道布局，回读不能只做集合比较。
- Custom1/Custom2 顶点流还依赖 Custom Data 的值与曲线，单纯保存 stream 名字不足以完成重建。
- URP 包和工程设置存在不代表批处理运行时已加载 URP，必须记录实际 Pipeline 类型。

## 本次推进范围

1. 建立颜色、平面方向、明确时长的最小执行控制；每条控制保存具体字段前后差异和未支持意图。该控制器是可审计的规则基线，不能称为训练出的 Planner。
2. 将静态材质匹配限制为候选筛选，永不直接批准正向训练；将 inferred 教程步骤与已支持步骤分开记录。
3. 修正顶点流顺序回读并标记尚未支持的 Custom Data；运行证据记录实际 Unity 版本和 Pipeline。
4. 使用同一 seed、同一资产集合，分别只改变颜色、方向或时长，做 Unity 编译、回读和动态像素对照。

## 后续评估标准

先完成一个有完整过程证据的制作方法，再扩展到多个独立来源。对尚未支持的制作动作补操作或执行器，对已有动作范围内的质量失败保存负例。普通测试失败不触发全局架构重写。

取得若干完整教程复现后，再冻结独立 Prompt 集，按类型和风格记录：有效生成率、Prompt 条件命中率、动态完整率、整体通过率和平均迭代次数。训练集与回归集按教程来源、Prefab 近似簇和资产共享组隔离。以这些实际指标更新“达成目标的可能性”，不以代码量、Schema 数量或测试数量替代。

## 本次运行结果

`prompt_execution_regression_r001` 已完成固定资产、固定生成 seed 和固定 runtime particle seed 的四条对照。Unity 编译 4/4，Prefab API 回读 4/4，共捕获 218 个有效帧。

| 对照 | 实际结果 |
|---|---|
| 蓝色 -> 红色 | 前景主色从蓝通道占优变为红通道占优 |
| 纵向 -> 横向 | 峰值轮廓约从 48x276 变为 276x48 像素 |
| 明确时长 0.15 -> 0.45 秒 | 最后可见时间约从 0.1406 变为 0.4200 秒 |
| 相同粒子种子 | 四条捕获的粒子随机种子列表完全一致 |
| 顶点流反例 | 仅调换 UV 与 Color 的顺序，回读准确拒绝该顺序不一致 |

这组数据证明有限参数控制已经传到画面，尚不证明整体审美或通用生成能力。实际画面偏暗，现有材质模板仍未形成教程中的明确主电流。

初次运行记录同时确认一个关键阻塞：实际 Unity 为 `2022.3.62f3c1`，`active_render_pipeline_type=no_active_srp`。`-NoUpm` 回放没有加载配置中的 URP。正常 UPM、ASCII 路径、对齐权威工程当前 URP 14.0.12 包清单，以及官方 CLI 启动均复现包管理器 path undefined 错误。旧文档中的“URP 14 捕获”不能继续作为已验证事实。

回归最终状态为 `diagnostic_controls_pass_pipeline_mismatch`，所有正向训练资格为 false。目标工程和隔离工程的 CLI 结构检查均为 0 错误、0 警告，但该检查不覆盖运行时 Pipeline。

### 同日后续：真实 URP 已恢复

两个独立空工程和 IPC 边界诊断定位到批处理进程缺少 `ALLUSERSPROFILE`。UPM 读取 Windows 全局配置路径时调用 `path.join(undefined)`，而不是项目路径未传入。八个 EffectDemo 启动入口已共用进程级补齐/恢复逻辑，不改变系统环境、Unity 安装或用户现有进程。同一空工程从启动退出码 1 变为 0，staging 正常解析并加载 URP 14.0.12。

`prompt_execution_regression_urp_r002` 保持相同资产和 seed，完成 4/4 编译、4/4 API 回读、218 有效帧。四项运行报告都记录实际实例 `UnityEngine.Rendering.Universal.UniversalRenderPipeline`；颜色、方向、时长和同 seed 对照全部通过，最终状态为 `pass_parameter_controls_only`。

这解决了验证可信度，不等于解决成品质量。实际联系表仍明显偏暗，整体生成正例/SFT 资格仍为 false，完整动态材质证据仍有未枚举 MPB/全局 Shader 状态限制。另有 32 帧的故意管线不匹配反例：PNG 全有效，但图像和完整视觉训练资格均为 false。

独立代码复核后又补上“必须存在非空 Pipeline 实例”的前置条件。Unity 合成门禁测试证实：即使请求把 `no_active_srp` 设成预期值，也不能让空实例取得图像或完整视觉训练资格。该测试的合成输入与真实捕获分开保存。

当前最高收益的下一步是按完整教程做逐层材质复现。代码审查发现同一色值被同时写入粒子 Start Color、Color over Lifetime 和材质 Tint，颜色会相乘；当前 QFX 模板还保留黑色 DissolveColor、0.7 的 DissolveEdgeWidth，以及额外 UV/噪声输入。需通过独立层和固定颜色对照核实这些设置的具体影响，不能把“属性存在、贴图已绑定”当成正确制作，更不能用增加训练轮数替代修正。

验证记录：最终 544 项 Python 测试通过；真实 Unity 回放完成且无 C# 编译/捕获异常。主工程及隔离工程 CLI 结构检查均为 0 错误、0 警告。详见 `ERR-VFXPIPELINE-001`、`ERR-VFXDATA-021` 与 R002 `regression_report.json`。历史 R001 保留，不覆盖失败证据。

### 同日后续：颜色与教程对象已校准

`particle_color_calibration_r002` 完成11/11编译和回读、446真实URP帧，证明重复颜色乘法已被显式独立通道替代，历史Graph行为仍保留。完整生命周期键表、材质色继承和随机模式拒绝均有验证。

原视频局部审计纠正了两类知识错误：Photoshop图层操作不等于Unity支撑层；qi/trail002的RGB Mask不等于MainBolt的Alpha Clip。实际Fixed黑白闪包含可见黑形体，而不是Alpha消失。工程试验的具体键值仍标inferred。

R003已经按明确的URP校准模板产出可查看的0.3秒蓝白闪电局部Prefab，3/3编译/回读、123有效帧与机制对照通过。R002的Fixed源导出重建41帧像素一致；Blend跨捕获有小幅差异，原样重拍也有，因此严格像素报告仍保留失败，不提升训练资格。

这一结果提高了制作执行和知识证据的可信度，没有训练出新的正式生成模型。校准模板尚属明确实验选择，不能声称正常MaterialPlan已能自动选对Shader；下一步接入可检索的已验证配方及包资产来源，同时继续校准连续渐变捕获时序。
