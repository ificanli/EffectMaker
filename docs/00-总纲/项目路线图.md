# 项目路线图

## 阶段 0：建立工作基础

目标：明确 Unity 版本、渲染管线、目标平台、MCP 接入方式和资源管理规则。

完成标准：

- Unity 工程可以稳定打开和运行。
- MCP 可以读取场景、修改对象并保存结果。
- 有一个专门的特效测试场景。
- 文档和效果记录目录可持续维护。

## 阶段 1：打通 MCP 操作闭环

目标：验证 AI 是否能够通过 MCP 完成最小操作链路：

1. 读取当前场景和层级。
2. 创建 GameObject 和组件。
3. 修改 Transform、材质和粒子参数。
4. 运行、暂停和重置场景。
5. 获取截图、日志或运行状态。
6. 保存场景和预制体。

此阶段重点是确认能力边界，不追求最终视觉质量。

## 阶段 1.5：建立资料吸收体系

目标：把用户投喂和自主检索得到的源文件、教学视频、文章和参考项目，转化为可追溯、可验证、可复用的知识。

完成标准：

- 每份资料都有来源、授权、版本、状态和适用范围。
- 资料能够按时间戳、章节、资源模块或文件路径切片。
- 事实、推断、限制和未知内容被明确区分。
- 关键结论有知识卡片和 Unity/MCP 最小验证实验。
- `knowledge/index.md` 建立资料、卡片、实验、效果和资产的追踪关系。
- 过期、不可复现或授权不明的资料不会直接进入项目规范。

具体流程见[资料投喂与吸收流程](../30-操作指南/资料投喂与吸收流程.md)。

## 阶段 2：建立基础视觉模块

依次沉淀火花、烟雾、火焰、能量球、冲击波、激光、拖尾、溶解、扭曲和地面投影。

每个模块至少应包含：

- 独立测试场景或测试区域。
- 可调参数。
- 使用的技术说明。
- 截图或录屏。
- 性能记录。
- 可复用限制。

## 阶段 3：制作组合型技能

将基础模块组合为普通攻击、斩击、投射物、爆炸、闪现、护盾、治疗、雷电、火焰和冰冻等完整技能。

重点学习：

- 多层特效的空间关系。
- 前摇、爆发、持续和收尾节奏。
- 触发点与角色动作的同步。
- 预制体参数化和复用。

## 阶段 4：提升演出质量

加入角色挂点、命中反馈、地面和环境交互、动态光、摄像机震动、屏幕后处理和 Timeline 多阶段演出。

完成标准：特效不只是独立显示，而是能够与角色、场景和镜头形成统一的视觉反馈。

## 阶段 5：工程化和资产库

建立：

- 预制体目录和版本规则。
- 材质与 Shader 模板库。
- 常用纹理和网格库。
- 参数命名规范。
- 触发接口和事件规范。
- 性能预算和平台适配规则。
- MCP 常用操作和自动化脚本库。
- 每个效果的复盘记录。

## 阶段完成判断

阶段完成不能只看“效果能不能播放”，还要同时满足：

- 需求目标明确。
- 关键视觉结构可解释。
- 参数可调且命名清楚。
- 能在目标镜头下读清。
- 已经过至少一轮主动迭代。
- 有基本性能数据。
- 结果已经保存并记录。
